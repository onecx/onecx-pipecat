= Voice session

The application exposes a WebSocket voice endpoint at `/ws/voice`. A voice
session has two phases on the same socket:

. *Handshake* — plain JSON messages handled by `VoiceSession` until a valid
`start_session` has authenticated the user and pinned the agent.
. *Pipeline* — the session builds one long-lived Pipecat pipeline and hands the
socket to it. Pipecat's `FastAPIWebsocketTransport` and the OneCX frame
serializer carry all further traffic.

NOTE: Protocol version 2 replaces the earlier request/response turn protocol.
The client streams audio; the server detects the turns (or, with
`speech.turn_detection=client`, the client signals push-to-talk boundaries).

== Authentication and start

The connection is accepted without authentication and is authenticated by the
first client message. A `start_session` command carries the user's OneCX
tokens in the `apm_principal_token` and `authorization` fields. The session
then:

. verifies the token (signature, issuer, expiry) against the Keycloak JWKS;
. checks chat access for `chat_id` with the token propagated to the chat service;
. loads the chat's message history (newest `chat.history_max_messages`
`HUMAN`/`ASSISTANT` messages) to seed the LLM context after the system prompt;
a failure fails the start with `chat_not_accessible`, because a session that
silently forgot the conversation would be wrong;
. checks the user's existing voice permission with the `authorization` access
token;
. pins the agent configuration (provider, model, system prompt, skills, MCP
servers) for the whole session;
. builds the LLM (provider credentials are resolved from
`ONECX_CREDENTIALS__REFS`) and the speech services for the pinned language;
. discovers MCP tools once and keeps only those that resolve to `ALWAYS_ALLOW`.

Every step fails closed: a typed `error` event, then `session_closed` (reason
`start_failed`), then the connection closes with code `1008`. A failed start
leaves no state behind and cannot be retried on the same connection. Before a
valid `start_session`, malformed messages only produce `error{bad_command}`.

The endpoint takes no query parameters. A connection that presents any query
parameter (for example `?token=...`) is closed with code `1008` before it is
accepted.

== Pipeline

[source]
----
transport.input() -> session control -> STT -> transcript events -> user aggregator
  -> LLM -> TTS -> wire events -> transport.output() -> assistant aggregator
----

* `transport.input()` / `transport.output()` are Pipecat's
`FastAPIWebsocketTransport` with `OnecxFrameSerializer`.
* *Session control* handles `refresh_token`, `stop` and malformed commands.
* *STT*, *LLM* and *TTS* are Pipecat services (AWS Transcribe / Polly and the
agent's configured OpenAI, Ollama or Anthropic provider). With the `inmemory`
speech provider and `ONECX_LLM__PROVIDER_OVERRIDE=inmemory` deterministic
in-memory services are used for tests and local development.
* The user aggregator detects turns according to `speech.turn_detection`:
** `vad` (default): a Silero VAD (bundled model, CPU) starts the user turn when
it hears speech; the turn ends `0.6` s after speech stops once a transcript
arrived (`SpeechTimeoutUserTurnStopStrategy`). The client only streams audio.
** `client`: `ExternalUserTurnStrategies`; turns are delimited by the client
(push-to-talk).
* The LLM context holds the composed system prompt and one tool schema: the
allowed MCP tools plus `activate_skill` when the agent has usable skills.
MCP tool calls go through `VoiceSession.invoke_tool`, which keeps the
`ALWAYS_ALLOW` check, the no-redirect rule and the user-token propagation.
* The pipeline idle timeout is `ONECX_PIPELINE__IDLE_TIMEOUT_SECS` (default:
disabled; the session ends at token expiry).

== Client to server

Messages are JSON objects with a `type` field.

[cols="1,3",options="header"]
|===
| `type` | Meaning

| `start_session`
| Handshake only. `agent_id`, `chat_id`, `apm_principal_token`, optional `authorization`.

| `user_started_speaking`
| Client turn detection only: push-to-talk press. Starts a user turn and interrupts the assistant if it is speaking (barge-in).

| `audio`
| `audio`: base64 PCM16 mono at `speech.sample_rate_hz`. With VAD, stream continuously from `session_ready` on (send silence while muted or stop sending); otherwise send chunks between started and stopped.

| `user_stopped_speaking`
| Client turn detection only: push-to-talk release. Ends the user turn; the transcript goes to the LLM.

| `refresh_token`
| `apm_principal_token` (and optional `authorization`). Replaces the session tokens; must belong to the same user.

| `stop`
| Ends the session; the server answers `session_closed{client_stopped}` and closes with 1000.
|===

Anything else (invalid JSON, unknown `type`, invalid base64) is answered with
`error{bad_command}`; the session continues.

== Server to client

[cols="1,3",options="header"]
|===
| `kind` | Meaning

| `session_ready` | Handshake done; carries `session_id`, `agent_id`, `schema_version`, `protocol_version`.
| `degraded_capability` | An MCP server was unreachable at discovery; its tools are missing.
| `transcript` | `text` and `state` (`PARTIAL` interim, `FINAL`). Only the final text becomes a durable entry.
| `user_started_speaking` / `user_stopped_speaking` | A user turn started (while the assistant speaks: a barge-in) or ended. Sent in both turn-detection modes.
| `assistant_text` | A streamed chunk of the text being spoken (`text`), in step with the audio.
| `assistant_audio` | Base64 PCM16 `audio` with `sample_rate`, `num_channels`.
| `bot_started_speaking` / `bot_stopped_speaking` | Playback state of the assistant.
| `interrupted` | The user barged in; drop queued assistant audio.
| `turn_complete` | `entry_id` of the persisted assistant entry; sent only after it was persisted.
| `error` | `code` and `message`; see below.
| `session_closed` | `reason`; the last message before the socket closes.
|===

Example turn with server VAD:

[source,json]
----
{"type": "audio", "audio": "AAAB..."}
{"type": "audio", "audio": "AAAB..."}

{"kind": "user_started_speaking"}
{"kind": "transcript", "text": "what is the weather", "state": "FINAL"}
{"kind": "user_stopped_speaking"}
{"kind": "bot_started_speaking"}
{"kind": "assistant_audio", "audio": "AAAA...", "sample_rate": 16000, "num_channels": 1}
{"kind": "assistant_text", "text": "It is sunny."}
{"kind": "bot_stopped_speaking"}
{"kind": "turn_complete", "entry_id": "abc:2"}
----

With client turn detection the audio is wrapped in `user_started_speaking` and
`user_stopped_speaking` commands.

== Turns, barge-in and persistence

* *Turn:* speech followed by a pause (VAD) or `user_started_speaking`, audio,
`user_stopped_speaking` (client). The user aggregator adds the final transcript to the
LLM context and triggers the LLM; the reply is spoken sentence by sentence.
* *Barge-in:* a user turn that starts while the assistant speaks (detected
speech, or `user_started_speaking`) makes the user
aggregator broadcast an `InterruptionFrame`. Pending LLM and TTS output is
cancelled, the output transport drops queued audio, the client receives
`interrupted`, and the assistant aggregator closes the turn as interrupted.
* *Persistence* is driven by the aggregators' turn events and writes to the
anchored chat (onecx-chat-svc, with the user's current token; the in-memory
backend is for tests). The user turn ends
with one `HUMAN` entry (empty or noise-only input stays ephemeral). The
assistant turn ends with one `ASSISTANT` entry with status `COMPLETED` or
`INTERRUPTED`, containing the text that was actually spoken. `turn_complete` is
sent only after the assistant entry is stored. If nothing had been spoken yet
when the user interrupted, no assistant entry is written. chat-svc's `Message`
has no status field, so an `INTERRUPTED` entry is stored as its spoken text.
* *Persistence failure:* `error{persistence_failed}` and no `turn_complete`; no
history is fabricated. Pipecat starts the LLM before the user-turn event
fires, so after a failed `HUMAN` write the reply of that turn is spoken but
neither persisted nor acknowledged.

== Errors

The `error` event carries one of the following codes.

Start: `authentication_failed`, `chat_not_accessible`, `voice_not_permitted`,
`config_unavailable` (agent configuration, provider/model, credential or LLM
setup unusable), `unsupported_language` (no AWS speech profile for the pinned
language).

Running session:

* `token_expired` — tokens expired; followed by `session_closed{token_expired}`
and close code 1008. Checked periodically, also while idle.
* `principal_mismatch` — `refresh_token` for a different user; not applied.
* `illegal_state` — a command in the wrong state (for example a second `start_session`).
* `bad_command` — malformed client message.
* `stt_failed`, `llm_failed`, `tts_failed` — non-fatal service failures; the
session stays usable for the next turn.
* `persistence_failed` — see above.

== Closing

The session ends on `stop`, token expiry, a failed start or client disconnect.
In every case the Pipecat worker is cancelled, the final events are sent and the
socket is closed (1008 on start failure and expiry, 1000 otherwise).

== Speech provider and language

The speech provider and its language mapping come from configuration (see
xref:configuration.adoc[Configuration]). With the `aws` provider the pinned
language selects the AWS Transcribe language and the Amazon Polly voice; a
language without a profile fails the start with `unsupported_language`.
