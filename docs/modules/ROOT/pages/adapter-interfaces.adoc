= Adapter interfaces

The application composes a set of replaceable adapters. Each capability is a
`typing.Protocol` in `onecx_pipecat/adapters/`. The OneCX boundaries
(authentication, agent configuration, chat, permission, MCP) ship only their
real implementation, which `onecx_pipecat/adapters/factory.py` always builds;
tests substitute fakes from `tests/fakes.py`. Persistence ships onecx-chat-svc
(`persistence.backend=chat`, default) and an in-memory implementation; speech and LLM are Pipecat services
(see `onecx_pipecat/services/`). Swapping a capability means
writing a new class that satisfies the same `Protocol` and pointing the
corresponding factory function at it.

== Authentication

* Protocol: `AuthAdapter` — `authenticate(apm_principal_token) -> Principal`,
  `is_expired(token) -> bool`, `refresh(token) -> Principal`,
  `service_token() -> str`
* Implementation: `JwtAuthAdapter`

The `apm_principal_token` is the OneCX token the client carries in the
`start_session` command. `authenticate` resolves it to a `Principal`;
`is_expired` reports whether a token whose session is already open has since
expired (driving `token_expired`); `refresh` resolves a fresh token
presented by a `refresh_token` command; `service_token` returns Pipecat's own
client-credentials token.

`ClientCredentialsAuth` (an `httpx.Auth`) requests that token from
`auth.token_endpoint` (default: the issuer's Keycloak token endpoint) with
HTTP Basic `client_id`/`client_secret`, caches it until 30 s before expiry,
and attaches it as `Authorization: Bearer` to every ai-provider, chat, and
permission call, next to `apm-principal-token`. A failed token request fails
that call closed.

`JwtAuthAdapter` verifies the token against a Keycloak JWKS. `auth.jwks` is an
embedded document or a URL; empty fetches the issuer's
`/protocol/openid-connect/certs` on first use. `set_jwks(jwks)` pins an
explicit set (an embedded `{"keys": [...]}` document, a bare list of JWKs, or
a single JWK) that is never refetched. `authenticate` decodes the token with
RS256, checking signature, `issuer`, and expiry; `is_expired` decodes without re-verifying expiry and reports whether `exp` is in the past.

The key used for a token is chosen by the token's `kid` header, so a JWKS that
carries several keys (a rotated set) is used correctly: `authenticate` reads
the unverified `kid` and verifies against the matching key. An unknown `kid`
refetches a URL-based JWKS (at most once a minute, so random `kid` values
cannot force repeated fetches); a `kid` still unknown afterwards is rejected,
and a token with no `kid` falls back to the first key in the set.

== Agent Configuration

* Protocol: `AgentConfigAdapter.pin(tenant_id, agent_id,
  apm_principal_token) -> AgentConfigSnapshot`
* Implementation: `HttpAgentConfigAdapter`

The snapshot is pinned **once**, when the session starts, and is not re-read
for the lifetime of the session. `HttpAgentConfigAdapter` calls
onecx-ai-provider-svc
`GET {agent_config.base_url}/v1/agents/{id}/configuration` with the
`apm-principal-token` header and parses the `AgentConfiguration` payload:
`schemaVersion`, `agent.id`, `scaffold.systemPrompt`, and `mcpServers[]`
(`name`, `url`, `credentialRef`, `unlistedToolPermission`, `toolRules[]`).
It fails closed with `AgentConfigError` on `404`, `409`, any other error
status, an unreachable endpoint, an MCP server without `name`/`url`, or when
`voice.voiceEnabled` is not `true`.

== Chat Access

* Protocol: `ChatAdapter.load(chat_id, apm_principal_token) -> Chat`
* Implementation: `HttpChatAdapter`

Loads a chat by id as the user identified by the propagated token. Raises
`ChatAccessError` when the chat cannot be loaded; the session fails closed
with `chat_not_accessible`. `HttpChatAdapter` calls
`GET {chat.base_url}/internal/chats/{id}` with the `apm-principal-token`
header and reads `id`, `topic`, the owner `userId` and `participants[].userId`.
The internal endpoint is authorized by Pipecat's service token and does not
check the user's access to the chat, so the session requires the principal's
subject to be the chat owner or a participant; otherwise the session fails with
`chat_not_accessible`. A user-scoped `GET /v1/chats/{chatId}` is requested
in https://github.com/onecx/internal-tasks/issues/995[onecx/internal-tasks#995]
and should replace this stand-in. This assumes the configured subject claim
equals the chat-svc `userId`.

== Speech

Speech is no longer an adapter. `onecx_pipecat/services/speech.py` builds
Pipecat STT and TTS services per session for the pinned language
(`build_stt_service`, `build_tts_service`): `AWSTranscribeSTTService` and
`AWSPollyTTSService` for `aws`, or the deterministic `InMemorySTT` and
`InMemoryTTS` from `services/inmemory.py`.

== Persistence

* Protocol: `ConversationPersistence`, keyed by chat id --
  `append(chat_id, entry, *, apm_principal_token, user_id) -> id` and
  `history(chat_id, *, apm_principal_token, limit) -> list[{role, content}]`
* Chat: `HttpChatPersistence` (default)
* In-memory: `InMemoryPersistence` (tests and local runs)

`HttpChatPersistence` calls onecx-chat-svc with the service token and the
user's propagated `apm-principal-token`; failures raise `PersistenceError`.

* `append` sends `POST /internal/chats/{id}/messages` with `skipAIProcessing`
(so chat-svc stores the message without forwarding it to the AI service):
`HUMAN` becomes `{type: HUMAN, userId, text}`, `ASSISTANT` becomes
`{type: ASSISTANT, text}`. The `Message` schema has no status, so an
`INTERRUPTED` assistant entry is stored as the text that was actually spoken.
Other entry kinds are rejected. The id comes from the response body or the
`Location` header.
* `history` sends `GET /internal/chats/{id}/messages` (404 means no messages
yet), orders by `creationDate`, keeps `HUMAN` as `user` and `ASSISTANT` as
`assistant` (system, unknown and blank messages are skipped) and returns the
newest `limit` messages.

`InMemoryPersistence` assigns a stable entry id per key and preserves order.
It enforces `persistence.max_entries_per_session` by evicting the oldest entry
when the cap is exceeded.
== Permission

* Protocol: `PermissionAdapter` —
  `has_voice_permission(principal, apm_principal_token, authorization) -> bool`
* Implementation: `HttpPermissionAdapter`
* Tool policy: `resolve_tool_permission(snapshot, tool)`,
  `allowed_tools(snapshot, discovered)` (pure functions)

`HttpPermissionAdapter` calls the same public API the same way as the OneCX
permissions Quarkus extension:
`POST {permission.base_url}/v1/permissions/user/{voice_product_name}/{voice_app_id}`
with `{"token": <authorization>}`, the user's `Authorization` value from
`start_session`, and `apm-principal-token` as a header. permission-svc resolves
the user's roles from that access token (by default `realm_access/roles`,
which Keycloak does not put into the ID token) and returns
`{"permissions": {resource: [actions]}}`;
voice is granted when `permission.voice_action` is listed under
`permission.voice_resource`. A missing `authorization`, any error status, or
an unreachable endpoint fails closed (no voice permission).

Tool policy is data resolved by ai-provider, not by Pipecat. Actions use the
canonical vocabulary `DENY`, `ALWAYS_ASK`, and `ALWAYS_ALLOW`. For a
discovered tool, `resolve_tool_permission` uses:

. The matching `toolRules[]` entry of the tool's MCP server.
. Otherwise that server's `unlistedToolPermission` (`DENY` when absent).
. A tool from a server that is not in the snapshot is `DENY`.

`allowed_tools` returns only the discovered tools that resolve to
`ALWAYS_ALLOW`; those are the tools the session advertises.

== MCP

* Protocol: `McpAdapter` —
  `discover(servers, headers) -> McpDiscovery`,
  `invoke(server, proposal, headers, args) -> McpToolResult`
* Implementation: `HttpMcpAdapter` (official `mcp` SDK, MCP Streamable HTTP)

MCP servers are **per agent**: the session passes the pinned snapshot's
`mcp_servers` (from `mcpServers[].url`) to `discover`; nothing is configured
globally except `mcp.timeout_seconds`. Each call opens an MCP session
(`initialize`) with the user headers from `propagated_headers`, matching
onecx-ai-provider-runtime: `apm-principal-token`, and the user's
`Authorization` from `start_session` forwarded as `UserAuthorization`.
Pipecat's service token is never sent to MCP servers. `discover` pages through
`tools/list` once per
session start and returns an `McpDiscovery` with the tools and a list of
`(server_name, reason)` pairs for servers that failed; a failing server is
surfaced as a `degraded_capability` event rather than aborting the session.
`invoke` runs `tools/call`; a tool error or an unreachable server is a
sanitized `McpToolResult(ok=False, error=...)`, otherwise `value` is the
structured content or the tool's text.

`credentialRef` is parsed but not yet resolved to MCP server credentials.
